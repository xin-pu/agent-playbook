## E1 · BenchChecker：用「仓库在不在训练集+补丁活没活下来」两段取证检测 bug-fix 基准污染，AUC≈0.9

- 获取日期：2026-10-18
- 来源 URL：https://arxiv.org/abs/2610.19447
- 本地原件：`Sources/04-benchmarks/.inbox/originals/arxiv-2610.19447-benchchecker-credibility.pdf`
- 适用范围：preprint，未经同行评议；覆盖 APR/bug-fix 基准的数据污染检测（开源与闭源模型皆可用，仅需文本输出+公开仓库历史）；不覆盖代码以外模态的污染检测。
- 证据等级：A
- 可提炼要点：
  1. 两段取证：第一段用代码前缀探针推断仓库是否进入过训练快照（repository presence test）；第二段做补丁存在性验证——相似对齐 + 测试套件确认持久补丁仍在近期快照中。
  2. 原文核对的实验口径：StarCoder-15B/StarCoder2-15B/CodeGen2-16B（The Stack v2 训练）六个基准上 AUC 约 0.9；作者报告六个基准中超过 85% 的源仓库出现在训练快照、其测试样本过半与仓库史相关；对 SWE-bench Verified 与 Multi-SWE-bench 过滤污染样本后，中等难度档 resolved 率相对原口径变化两成以上（原文以相对幅度表述）。
  3. 背景声明（论文转引）：OpenAI 曾因污染担忧停止报告 SWE-bench Verified 分数——转引事实，等级止于 B，提升前需另找一手公告。
- 关闭条件：85%/20% 两处数字来自预印本实验节，未第三方复现；「OpenAI 停报」需回补一手来源后方可关。

## E2 · Agent 评测 harness 自身的可靠性审计：五条状态完整性不变量 + 已知答案控制

- 获取日期：2026-10-18
- 来源 URL：https://arxiv.org/abs/2610.16067
- 本地原件：—
- 适用范围：preprint，未经同行评议；覆盖 agent 基准评分软件（oracle/harness）缺陷的注入-检测实验与真实基准审计；不覆盖被评 agent 能力结论。
- 证据等级：A
- 可提炼要点：
  1. 视角：把评测 harness 当软件系统审计——提出 oracle-integrity 审计法（5 条状态完整性不变量 + 3 类 known-answer 控制），注入 7 类 oracle 缺陷跨两任务域+一合成域全部检出，修复后的 oracle 无误报。
  2. 实战发现：应用到一个 agent 基准后暴露「奖励函数在 run 结束后、计分前改变环境状态」的缺陷；4,320 episodes 的重放审计表明评分受配置影响——与首轮「工具层固定为评测控制变量」的结论形成镜像：变量固定之外，评分器自身也要完整性验证。
- 关闭条件：未取原件，具体基准名与缺陷编号待核对（摘要匿名化表述）；需 PDF 复核实验对象后可关。

## E3 · DIB-Bench：部署完整性盲区——越强的评判器越放行篡改部署（88.6% → 94.1%）

- 获取日期：2026-10-18
- 来源 URL：https://arxiv.org/abs/2610.21135
- 本地原件：—
- 适用范围：preprint，未经同行评议；覆盖「只评输出」的评测范式对运行时栈篡改的不敏感性度量（7,560 计分样本、6 类篡改、regex→LLM judge→GPT-5-nano 评判器阶梯）；不覆盖真实生产事故证据。
- 证据等级：A
- 可提炼要点：
  1. 反直觉定量结论：评判器越强，对篡改输出的接受率越高——均值从规则式 88.6% 升至 GPT-5-nano 94.1%；输出-only 评测无法证明「被测的就是部署的」。
  2. 触发式篡改（评测套件上不可见）可产生 48–100% 的有害输出，且随模型能力上升；论文附 PAC 风格界说明输出采样检测不出该情形。
  3. 与 E2 合读构成「评测可信度」箱的两翼：E2 审 oracle 软件缺陷，本块审评估范式盲区；均支持「评测报告应登记运行时栈身份」这一可提炼口径。
- 关闭条件：6 类篡改的构造强度决定结论外推性，需原件核对 threat model 表述；第三方复现后可关。
