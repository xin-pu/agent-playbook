## E1 · AutoVend：线上决策到线下履约的长程自主售货经营基准

- 获取日期：2026-10-29
- 来源 URL：<https://arxiv.org/abs/2610.36980>
- 本地原件：—
- 适用范围：preprint，未经同行评议；O2O 商业场景的长程 agent 评测（卖家侧经营而非消费者购物）；覆盖「线上决策经物理执行产生成本」的闭环评估设计；不覆盖真实资金结算与多店铺泛化。
- 证据等级：A
- 可提炼要点：
  1. 评测主张：评估此类 agent 须超出单笔交易，检查线上决策是否转化为线下实际结果（成本由执行侧产生）。
  2. 归属：与本域 `agent-science-benchmark-wave`、`kwbench-gui-handoff-benches` 构成的「专业任务基准」主线相邻，合箱时可互引。
- 关闭条件：任务构成、判分器与泄漏防护细节在正文；补读后关。

## E2 · FeatureArc：在演化特性上考察 coding agent 的连续扩展能力

- 获取日期：2026-10-29
- 来源 URL：<https://arxiv.org/abs/2610.37434>
- 本地原件：—
- 适用范围：preprint，未经同行评议；编码基准的方法论增量：从「固定代码库上单请求」改为「在 agent 自己先前产出的代码上 successive extensions 并保持特性正确」；不覆盖生产仓库级长周期维护。
- 证据等级：A
- 可提炼要点：
  1. 缺口定位：特性随时间演化、每次扩展建立在此前代码之上，而现有特性类基准只评单轮请求。
  2. 设计：以特性演化序列组织任务，检查连续扩展后特性是否仍正确（判分细节在正文）。
  3. 与本域 `benchmark-integrity-coding`（2026-10-20 投递）同一子线。
- 关闭条件：任务规模/语言分布/基线分数未掌握；补原件或正文精读后关。

## E3 · LiveSearch：把问题写成可执行校验码的「活」金融检索基准

- 获取日期：2026-10-29
- 来源 URL：<https://arxiv.org/abs/2610.37166>
- 本地原件：—
- 适用范围：preprint，未经同行评议；专业源时效检索（行情/利率/披露随日期失效）；覆盖「金标随市场移动而过期、泄漏后奖励回忆而非搜索」问题的机制设计；不覆盖非金融专业检索。
- 证据等级：A
- 可提炼要点：
  1. 机制：问题以可执行 verifier code 表达，使答案按当前日实时判定，避免静态标注的金标失效（questions as executable verifier code）。
  2. 污染视角：把「泄漏进训练数据→奖励回忆」作为基准设计失配显式处理，与本域 `agent-benchmarks` 箱既有的 contamination 主线（2610.36405 审计基准等）互引。
- 关闭条件：verifier 的表达式覆盖面与反例（不可执行问题）未核；补正文后关。

## E4 · TeamGym：分布式信息下的团队决策 gym（法律/金融/医疗/软件工程语料）

- 获取日期：2026-10-29
- 来源 URL：<https://arxiv.org/abs/2610.37571>
- 本地原件：—
- 适用范围：preprint，未经同行评议；以真实领域语料构造「信息分布于参与者」的团队决策评测与训练环境；覆盖 LM agent 的团队级整合能力；不覆盖人类-机器混合机构的长期治理。
- 证据等级：A
- 可提炼要点：
  1. 批评口径：AI agent 主要在孤立状态下被训练与评测，而许多现实决策需要团队整合分布在各参与方的信息。
  2. 语料来源：legal、finance、medical、software engineering 四类真实语料构造任务（构造细节在正文）。
  3. 与 `2610.37624`（CrossProfile，见 02-agent 台账）互补：一个给环境、一个做诊断，合箱时同置一条线。
- 关闭条件：任务数、成功判据与基线数值未掌握；补原件后关。
